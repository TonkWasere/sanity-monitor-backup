## Метод-дополнения (запись №20, 11.10)
1. **CDN-превью ТГК живут одну выдачу:** ссылки `cdn4.telesco.pe/file/…` из HTML `t.me/s/…` отдают 404 при попытке скачать позже (даже через минуты, с Referer). Рабочий способ: свежий снап страницы → МГНОВЕННАЯ скачка ссылок из того же HTML в одном процессе (кейс 11.10: 4/4 JPEG получены из повторного снапа 12:27, все ссылки снапа 12:22 — 404).
2. **MEGA > 50 MiB — только curl-resume-схема:** монолитный stream.read-загрузчик (29-a) на 193 MiB дважды умирал молча (обрыв без исключения, процесс на 2 %). Рабочая схема: (а) `a:g,g:1` → url; (б) `curl -C - --retry 8 --retry-all-errors --speed-limit 10240 --speed-time 30` — докачивает шифрованное тело с Range-resume; (в) отдельный проход: AES-CTR continuous counter от iv по чанкам + MAC-чек. Примечание: MAC-чек на 193 MiB не воспроизвёл состояние (IndexError в хвосте чанка 458669 % 16=13) — сверка SHA256 с локальным эталоном строже и достаточна, когда файл уже известен.
3. **Реакции постов форума** — атрибут поста `reactionCounts` (словарь reactionId→счётчик) в near-выдаче; `likesCount` рядом. Реакции Relationship в `included` пустые — не источник.
4. **Хронометраж подачи = стандартная сверка**: для каждого нового официального материала фиксировать время первого появления на каждом ресурсе (кейс 11.10: форум 11:40:45 → ТГК 12:01:28, форум-первый на 20:43; против кейса набора №2: Steam → ТГК, форум — никогда).
