## 4. Паттерн «минимум следов»: как чистка выглядит снаружи

**Наблюдение Санити (02.10, вечер):** видимых указаний ПОЧЕМУ нет в принципе; выглядит как «подметание» с минимумом действий, чтобы некоторых моментов «вообще не существовало» — по крайней мере с тз человека, который тыкал тред вопросами. Формализация по нашей фактуре:

| Маркер | Наблюдение | Эффект снаружи |
|---|---|---|
| Причина сноса | нигде не публикуется: ни публично, ни автору (Flarum без reason-расширений; модерлога нет) | у вопроса «почему» нет адресата — даже у автора |
| Вид гостю | скрытый пост не отдаётся вообще — номер просто пропущен | нет ни плейсхолдера, ни дыры в UI |
| Счётчик | commentCount НЕ пересчитывается (= числу комментариев в БД/индексе; 407 при недостижимости #415) | тред «выглядит полным», число не выдаёт чистку |
| Выживший контент | не редактируется (телега #381: diff=0 между 19.09 и 02.10) | только вычитание, никогда переписывание — нет «швов» |
| Лок | оформлен как рутина («Вопросы для QnA успешно отобраны… закрываем тред») | модерационное действие выглядит естественным завершением |
| Контекст | соседи сносятся вместе с целью (#376/378/382/383/385 при паре #384+#389) | не остаётся обрывков, по которым эпизод восстанавливается |
| Тайминг | часы–дни после одобрения (#415 ~2ч; пара — в пределах 19.09→28.09) | удаление происходит вне внимания публики |

**Механика:** каждый акт = один флаг isHidden (для треда — isLocked + один бытовой пост). Flarum по умолчанию даёт модератору «идеальный ластик»: гостевой API исключает скрытое, публичного журнала нет, счётчик не меняется. «Минимум следов» — не столько специальная маскировка, сколько дефолтная поверхность модерации Flarum; exbo.net сверху ничего не добавляет.

**Подметание vs модерация:** обычная модерация оставляет провокацию (контекст правила) и/или указывает причину; здесь сносится ПАРА «наезд+ответ» вместе с соседями, причина не называется, тред запирается с бытовой формулировкой. Это не наказание нарушителя, а восстановление состояния «обмена не было». Для случайного читателя эпизод не «удалён» — он «никогда не существовал»: номер пропущен, счётчик сходится, лок объяснён. Метод работает против именно той аудитории, которая не архивирует.

**Проверка из-под акка (02.10, ~20:35 UTC — закрыла открытый пункт протокола):** автор #415 видит ТОЛЬКО факт скрытия — свёрнутое, «засеренное»/обесцвеченное сообщение; никаких плашек, причин, ссылок на правила или имени модератора. Любой другой источник (другой аккаунт, гость) сообщения не видит вообще; гостю номер пропущен. Итог — 4-уровневый градиент информированности: **моды (всё) → автор (только факт скрытия) → другие юзеры (ничего) → гость (пропуск номера)**. Причина не раскрывается ни на одном наблюдаемом уровне; текст автора остаётся в БД цел (hide ≠ purge). Следствие: установить «почему» извне можно только сравнительным методом (контрольные пары) — причин как класса не существует, их нечитаемое множество пусто по определению.

**Следствие для кампании:** против бесследного сноса работает только внешняя следовая база — снапшоты «до/после» с таймстампами. Дампы 19.09 23:11 — единственное доказательство существования обмена #384+#389. Отсюда дисциплина: снап сразу после постинга + контрольный срез через сутки; гость видит только живое, серое состояние — только из-под акка.
