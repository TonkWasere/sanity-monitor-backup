Следствия:

1. **Контент сохранён в БД** — в обоих случаях использован стандартный Flarum soft-hide; жёсткое удаление (purge) не применялось **ни разу за всю кампанию**
2. Доступ автора к контенту сохранён → автор всегда может сделать дамп/скрин скрытого (см. §2)
3. Последняя слепая зона гостевой поверхности закрыта: тип сноса теперь **наблюдаем автором** — триада верификации (гостевой API + вид автора + скрины) расширена до **тетраэдра** (+профиль)

## 2. Профильный канал — 4-я поверхность верификации

Пятиуровневая таблица информированности (финальная редакция §4 нотки 14i):

| Уровень | Контент скрытого | Факт скрытия | Причина сноса |
|---|---|---|---|
| Модерация | видит | видит | знает |
| Автор — в треде | видит (серым) | видит | не видит |
| **Автор — в профиле** | **видит ВСЕ свои скрытые списком** | **видит** | **не видит** |
| Другие юзеры | не видят | не видят | не видят |
| Гость / API | не видит («номера нет») | не видит | не видит |

**Протокол отчетности и ловли (для Санити):**

1. Профиль → посты/активность → серые свёрнутые посты = полный список скрытого
2. Для отчетности: скрин каждого серого поста в раскрытом виде + копия текста + дата фиксации — это единственная поверхность, где одновременно видны и контент, и факт скрытия
3. **Первое действие при любом подозрении на снос — профиль:** пост серый → hide (тип события документирован, контент уже у нас); поста нет даже в профиле → **purge** (новый, более агрессивный тип — фиксировать немедленно, событие иного класса)
4. Профиль работает как мониторинг собственных скрытых без API и без ссылок — регулярная перепроверка после волн активности в тредах
